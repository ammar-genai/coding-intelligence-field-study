01 / The study

Separate the product from the model.

Phase 1 measured the complete assistant experience. Phase 2 held Pi constant and changed only the model route. Between them, the study distinguishes product advantage, model capability, and workflow design.

Q1

Which assistant should lead?

Codex was the strongest default integrator; Claude was the strongest independent reviewer.

Q2

Is OpenCode worth it?

Yes, when model flexibility and bounded open-model work matter more than native polish.

Q3

Can cheaper models implement?

Yes. Qwen and GLM passed hard tasks inside Pi, provided the work was explicit and verifiable.

Q4

Should every task be distributed?

No. Distribution improves separation and auditability, but the measured route was 3.57× slower than solo Codex.

07 / Recommended operating model

Frontier judgment at the top. Economical execution underneath.

This architecture combines the strongest observed product and model behaviors without pretending every task needs a committee.

01 / PlanCodex + Sol

Define interfaces, risk, ownership, and executable acceptance checks.

02A / BuildQwen worker

Small bounded component with a fast test.

02B / BuildGLM worker

Hard asynchronous unit where latency is acceptable.

02C / ChallengeClaude review

Independent risk review for high-impact changes.

Evidence handoff: patches · tests · reports
03 / IntegrateCodex final gate

Resolve conflicts, run the complete suite, inspect behavior, and report residual risk.

Control rule

Keep assignments non-overlapping. Require an early edit, fixed timeout, saved patch, private verification, and frontier fallback.

Conclusion

Build a team of roles, not a leaderboard of brands.

Codex is the default lead. Claude is the independent reviewer. OpenCode is the flexible worker harness. Pi is the neutral lab. Sol plans; Qwen executes cheaply; GLM handles hard asynchronous work; Fable buys speed; Kimi stays guarded until completion is more reliable.
